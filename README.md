# kg-practice-2026: граф знаний, поиск и агент над статьями по математике

Репозиторий эксплуатационной практики осени 2026/27. За шесть недель группа строит систему, которая
читает научные статьи по математике и математической физике в PDF, извлекает из них утверждения,
определения, доказательства, формулы, литературу и ссылки, записывает извлечённое в граф знаний,
ищет по нему и отвечает на вопросы агентом с инструментами. Каждый студент пишет один из десяти
модулей извлечения и прогоняет библиотеку всей группы на своих 1000 статьях.

## Студенту: что нужно сделать

### Что получится в итоге

За шесть недель у каждого студента появляются четыре результата.

1. **Свой модуль** — программа на Python, которая находит в научной статье один вид объектов:
   метаданные, разделы, теоремы и леммы, определения, формулы, список литературы, доказательства,
   ссылки, понятия или предметные области (вариант определяет, какой именно). Модуль работает
   внутри общей библиотеки группы, и его качество измеряется на ручном эталоне.
2. **Граф знаний своего набора** — 1000 статей, которые выдал руководитель, обработаны всеми
   десятью модулями группы и записаны в графовую базу GraphDB: какие в статьях теоремы, где они
   доказаны, на какие леммы опираются доказательства, какие понятия определены, какие работы
   цитируются.
3. **Поиск по своему набору**, который находит фрагменты статей по смыслу запроса и дополняет их
   связями из графа.
4. **Агент** — языковая модель, которая отвечает на вопросы по статьям и вызывает для этого модули
   и запросы всей группы как инструменты; на защите студент показывает, из какого места какой статьи
   взят каждый факт ответа.

### Что разобрать в репозитории

Файлы удобно читать в таком порядке.

1. `КОНСПЕКТ.md` — зачем нужна практика, как устроена работа группы, расписание двенадцати встреч,
   из чего складывается оценка.
2. `notebooks/00_Общая_часть.ipynb` — блокнот, который проводит одну статью arXiv через всю
   систему. Его стоит запустить в Colab и пройти целиком. Блокнот показывает, что статья после
   общей основы base превращается в объект `Doc` — текст статьи с абзацами, предложениями, шрифтом
   и формулами. Модуль получает `Doc` и возвращает фрагменты текста с классами и связи между ними,
   из результатов модулей строится граф, и каждый модуль одновременно служит инструментом агента.
   Раздел 8 блокнота показывает, как версия модуля, написанная студентом, заменяет базовую.
3. `ЗАДАНИЯ.md` — постановка своего задания (как её найти — ниже).
4. `варианты/Вариант_NN.md` — подробности своего варианта по этапам: что делает базовая версия
   модуля, что студент добавляет на каждом этапе, какие трудные случаи встретятся.
5. `mathkg/modules/mNN_*.py` — код базовой версии своего модуля: с него начинается работа.
6. `ИНСТРУКЦИЯ_git.md` — как подготовить доступ к репозиторию и как сдавать этапы; прочитать до
   первого этапа.

`ОБЩАЯ_ЧАСТЬ.md` и `02_МОДЕЛЬ_ДАННЫХ.md` — справочники по пакету `mathkg` и модели данных; к ним
обращаются по мере надобности. Код в `mathkg/` целиком разбирать не нужно: достаточно своего модуля
и тех функций, которые вызывает блокнот этапа.

### Где своё задание

Руководитель назначает каждому студенту номер варианта NN от 01 до 10. Номер варианта — это номер
модуля, номер ветки в репозитории и номер папки сдачи. Например, у варианта 7:

| Что | Где |
|---|---|
| постановка задания: цель, что находит модуль, критерии приёмки | `ЗАДАНИЯ.md`, строка 7 таблицы в начале файла и раздел «Задание 7. Доказательства» |
| подробности по этапам | `варианты/Вариант_07.md` |
| базовая версия модуля | `mathkg/modules/m07_proofs.py` |
| свой модуль (создаёт студент) | `modules/m07_proofs.py` |
| свой ручной эталон | `gold/m07.jsonl` |
| своя ветка и папка сдачи | `student-07`, `students/07_фамилия/` |
| задание очередного этапа | блокнот `notebooks/stageNN_….ipynb`; блокноты появляются в репозитории по мере лекций |

### Как свой модуль встраивается в систему

Все модули группы работают с одним и тем же текстом статьи (`Doc` от base) и возвращают результат в
одном формате: фрагменты (например, «доказательство с 120-го по 980-й символ, страница 4») и связи
(«это доказательство доказывает теорему 2.1»). Поэтому результаты разных модулей складываются в
один граф, а модули могут пользоваться результатами друг друга: модуль доказательств (m07) берёт
теоремы, которые нашёл модуль утверждений (m03).

Встраивание идёт так.

1. Студент копирует базовую версию своего модуля в `modules/mNN_<название>.py` и улучшает её:
   сначала правилами, затем моделью Hugging Face, затем языковой моделью (этапы 2–6).
2. Три вещи в модуле не меняются: имя инструмента (`name` в декораторе `@tool`), список модулей,
   от которых он зависит (`requires`), и формат результата. От них зависят модули соседей, граф и
   агент. Всё остальное внутри функции студент пишет как считает нужным.
3. Перед сдачей модуль проходит проверку контракта (`check_module`) и оценку по эталону
   (`evaluate`) на общем тестовом наборе.
4. Студент сдаёт модуль запросом на слияние своей ветки в `main`. После приёма модуль появляется у
   всей группы: ячейка подключения в блокноте каждого студента загружает его вместо базовой версии.
   С этого момента модуль работает на 1000 статьях каждого студента, его находки попадают во все
   графы группы, и агент вызывает его как инструмент.
5. На сборках (встречи 5 и 7) руководитель прогоняет все модули группы на тестовом наборе и
   показывает таблицу: прошёл ли модуль проверку, сколько нашёл, сколько времени тратит. Модуль,
   который не прошёл проверку, в сборке заменяется базовой версией.

### Как идёт работа

Каждая встреча — лекция около часа и задание очередного этапа в виде блокнота. Этап сдаётся через
две встречи после своей лекции. Работа с этапом всегда одинакова: открыть блокнот этапа в Colab,
выполнить первую ячейку (ячейку подключения), сделать задание, положить отчёт `REPORT.md` в папку
этапа на Google Drive, выполнить последнюю ячейку (ячейку сдачи) и открыть по напечатанной ссылке
запрос на слияние «Этап N: фамилия». Подробно — `ИНСТРУКЦИЯ_git.md`.

| Недели | Этапы | Что делает студент |
|---|---|---|
| 1 | 1–2 | обрабатывает свой набор общей основой base, разбирает текст статьи и ошибки base, копирует базовую версию своего модуля |
| 2–3 | 3–6 | улучшает свой модуль: правила и ручной эталон, модель Hugging Face, связи и общие идентификаторы, языковая модель; сборки 1 и 2 |
| 4 | 7–8 | прогоняет всю библиотеку группы на своих 1000 статьях, строит граф, пишет запросы SPARQL и свой инструмент запросов |
| 5 | 9–10 | строит векторный индекс фрагментов и поиск «вектор + граф» |
| 6 | 11–12 | собирает агента над инструментами группы и MCP-сервер, готовит итоговый отчёт и защиту |

## Запуск блокнота

**Google Colab.** Открыть `notebooks/00_Общая_часть.ipynb` (File → Open notebook → GitHub или
загрузка файла) и выполнить ячейки по порядку. GPU не нужен; блокнот выполняется за 3–5 минут.

**Свой компьютер.** Python 3.10 или новее:

```bash
git clone <адрес репозитория> kg-practice-2026
cd kg-practice-2026
pip install -r requirements.txt pandas sentence-transformers jupyter
jupyter notebook notebooks/00_Общая_часть.ipynb
```

Блокнот скачивает статью arXiv:2611.16131 и пишет все результаты в папку `work/`.

## Правила репозитория

* Вся работа студентов сдаётся сюда: каждый работает в своей ветке `student-NN` и сдаёт этап
  запросом на слияние в `main` с заголовком «Этап N: фамилия»; принимает запросы руководитель.
  Порядок — `ИНСТРУКЦИЯ_git.md`.
* Студент меняет только свои файлы: `modules/mNN_*.py`, `gold/mNN.jsonl`, `query_tools/qNN_*.py`,
  `eval/queries_NN.jsonl`, `vocab/concepts_NN.tsv`, `students/NN_фамилия/`. `mathkg/`, `ontology/`,
  `notebooks/` и `builds/` меняет руководитель.
* Замечания к общему коду — задачи (Issues) с меткой `base`, к модулям соседей — с меткой модуля
  (`m01`…`m10`).
* Данные в репозиторий не кладутся: статьи (PDF), наборы студентов, результаты прогонов, графы,
  векторы и индексы лежат на Google Drive (личная папка `practice2026/`, общий тестовый набор
  `kg_data/`). Токен GitHub, пароли GraphDB и ключи хранятся только в секретах Colab. Список
  исключений — `.gitignore`.
