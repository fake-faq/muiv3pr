# Общая модель данных практики

Модель данных у всех студентов общая. Классы и свойства берутся из двух онтологий:

* **MocassinPlus v2** (префикс `moc:`, `https://w3id.org/mocassinplus/ontology#`) — логическая,
  текстовая и источниковая структура математического документа: сегменты, утверждения, доказательства,
  формулы, понятия, происхождение извлечённых данных;
* **SciLibReco 2.1.0** (префикс `scilibreco:`, `https://scilib.ai/ontology/scilibreco#`) — модуль поверх
  MocassinPlus: авторы, организации, площадки публикации, ключевые слова, предметные области, УДК,
  связи понятий и публикаций, свойства формул.

Файлы онтологий выдаются вместе с заданием (`MocassinPlus_v2.ttl`, `SciLibReco.ttl`). Новые классы и
свойства студенты не вводят. Если нужного термина в онтологиях нет, это записывается в отчёт этапа как
замечание к модели и обсуждается с руководителем.

## 1. Ядро: что извлекают все

| Что в статье | Класс | Ключевые свойства |
|---|---|---|
| Статья | `moc:Document` | `rdfs:label` (заголовок), `scilibreco:hasTitle`, `scilibreco:hasAbstract`, `scilibreco:hasLanguage`, `moc:hasDOI`, `scilibreco:hasPublicationYear`, `scilibreco:publishedIn`, `scilibreco:hasAuthor`, `scilibreco:hasKeyword`, `scilibreco:hasConcept`, `moc:hasSegment`, `scilibreco:containsStatement`, `scilibreco:containsFormula` |
| Журнал или архив | `scilibreco:PublishingPlatform` | `scilibreco:hasName`, `scilibreco:hasPlatformType` («journal», «preprint»), `scilibreco:hasISSN` |
| Автор | `scilibreco:Author` | `scilibreco:hasName`, `scilibreco:hasNormalizedName`, `scilibreco:hasEmail`, `scilibreco:hasAffiliation` → организация |
| Организация | `scilibreco:Organization` | `scilibreco:hasName`, `rdfs:label` |
| Ключевое слово | `scilibreco:Keyword` | `scilibreco:hasName`, `scilibreco:hasNormalizedName`, `scilibreco:hasLanguage` |
| Заголовок, аннотация, ключевые слова | `moc:Title`, `moc:Abstract`, `moc:KeywordList` | `moc:hasText`, `moc:segmentOf` |
| Раздел | `moc:Section` (и подклассы `moc:Introduction`, `moc:Preliminaries`, `moc:ResultsSection`, `moc:ConclusionSection`) | `scilibreco:hasTitle`, `moc:hasNumber`, `moc:hasPart`, `moc:hasOrderIndex` |
| Абзац | `moc:Paragraph` | `moc:hasText`, `moc:hasOrderIndex`, `moc:hasStartOffset`, `moc:hasEndOffset`, `moc:hasPageNumber`, `moc:isPartOf`, `moc:nextSegment` |
| Теорема, лемма, предложение, следствие | `moc:Theorem`, `moc:Lemma`, `moc:Proposition`, `moc:Corollary` | `moc:hasText`, `moc:hasLabel` («Теорема 2.1»), `moc:hasNumber` («2.1»), `moc:isPartOf` → раздел, `moc:provedBy` → доказательство |
| Определение | `moc:Definition` | `moc:hasText`, `moc:hasNumber`, `moc:defines` → понятие |
| Доказательство | `moc:Proof` | `moc:hasText`, `moc:proves` → утверждение |
| Формула | `moc:Formula`, `moc:Equation` | `moc:hasPlainText` (текст из PDF), `moc:hasLatexSource` (если восстановлен), `moc:hasNumber` («2.3»), `scilibreco:isDisplayFormula`, `moc:occursIn` → сегмент |
| Понятие | `moc:MathematicalConcept` | `scilibreco:hasName`, `scilibreco:hasNormalizedName`, `scilibreco:hasDefinitionText`, `rdfs:label` |
| Упоминание понятия | — (связь) | сегмент `moc:mentionsConcept` → понятие |
| Ссылка на утверждение внутри статьи | — (связь) | сегмент `moc:refersToTheorem` / `moc:refersToStatement` / `moc:refersToDefinition` → утверждение; ссылка на замечание или пример — `moc:refersTo` |
| Использование в доказательстве | — (связь) | доказательство `moc:usesLemma` / `moc:usesTheorem` / `moc:usesResult` / `moc:usesDefinition` → утверждение или определение (подсвойства `moc:dependsOn`) |
| Список литературы | `moc:Bibliography`, `moc:ReferenceEntry` | `moc:hasPart`, `moc:hasText`, `moc:hasNumber`, `moc:hasDOI` |
| Ссылка на литературу в тексте | — (связь) | сегмент `moc:citesBibliographicReference` → запись списка литературы |

Ядро собирается из результатов десяти модулей; что даёт базовая версия каждого модуля и что добавляет студент — в разделе 6.

### Происхождение каждого факта

Каждый извлечённый сегмент и каждое понятие несёт сведения о том, как оно получено:

| Свойство | Значение |
|---|---|
| `moc:hasExtractionMethod` | `rule` (правило, регулярное выражение, признаки шрифта), `model` (классификатор или модель NER), `llm` (генеративная модель), `manual` (ручная правка) |
| `moc:hasConfidence` | число от 0 до 1; у правил — 1.0 или оценка точности правила на контрольной выборке |
| `moc:generatedBy` | запуск извлечения `moc:ExtractionRun` |
| `moc:hasStartOffset`, `moc:hasEndOffset` | позиции фрагмента в очищенном тексте статьи (символы, отсчёт от 0) |
| `moc:hasPageNumber` | страница PDF |
| `moc:extractedFrom` | исходный документ `moc:SourceDocument` (PDF статьи) |

У запуска `moc:ExtractionRun` указываются `moc:wasExtractedAt` (дата и время), `moc:wasExtractedBy` →
инструмент `moc:ExtractionTool` (имя модели Hugging Face или «regex-rules-v1») и
`moc:hasExtractionMethod`. Это позволяет на защите ответить на вопрос «откуда взялась эта тройка».

### Соглашение о литералах (из SciLibReco)

Значения свойств `moc:` и `scilibreco:` записываются без метки языка: `moc:hasText "…"`. Язык
статьи указывается свойством `scilibreco:hasLanguage "ru"`, язык сегмента — `moc:hasLanguage "ru"`.
Подпись для показа человеку — `rdfs:label "…"@ru` с меткой языка. Год публикации — целое число
(`scilibreco:hasPublicationYear 2019`): так задан диапазон свойства в онтологии.

## 2. Правила построения IRI

Пространство имён экземпляров — `mp:` = `https://w3id.org/mocassinplus/resource/` (MocassinPlus отводит
его для ресурсов). IRI строятся детерминированно, чтобы графы разных студентов совпадали в общих
объектах.

| Объект | Шаблон IRI | Пример |
|---|---|---|
| Статья | `mp:doc/{doc_id}` | `mp:doc/A04571` |
| Заголовок, аннотация, список ключевых слов (m01) | `mp:doc/{doc_id}/title`, `…/abstract`, `…/keywords` | `mp:doc/A04571/abstract` |
| Абзац (base) | `mp:doc/{doc_id}/p-{NNNN}` | `mp:doc/A04571/p-0031` |
| Выключная формула (base) | `mp:doc/{doc_id}/f-{NNNN}` | `mp:doc/A04571/f-0012` |
| Строчная формула (m05) | `mp:doc/{doc_id}/if-{NNNN}` | `mp:doc/A04571/if-0140` |
| Раздел, подпись (m02) | `mp:doc/{doc_id}/sec-{NNNN}`, `…/cap-{NNNN}` | `mp:doc/A04571/sec-0003` |
| Утверждение (m03) | `mp:doc/{doc_id}/st-{NNNN}` | `mp:doc/A04571/st-0004` |
| Определение (m04) | `mp:doc/{doc_id}/def-{NNNN}` | `mp:doc/A04571/def-0002` |
| Доказательство (m07) | `mp:doc/{doc_id}/prf-{NNNN}` | `mp:doc/A04571/prf-0005` |
| Список литературы, запись (m06) | `mp:doc/{doc_id}/bib`, `…/ref-{NN}` | `mp:doc/A04571/ref-07` |
| Исходный PDF | `mp:source/{doc_id}` | `mp:source/A04571` |
| Понятие | `mp:concept/{slug}` | `mp:concept/banakhov-prostranstvo` |
| Именованное утверждение («теорема Лиувилля») | `mp:statement/{slug}` | `mp:statement/liuvillya-teorema` |
| Персона, автор | `mp:person/{slug}` | `mp:person/ivanov-a-b` |
| Организация | `mp:org/{slug}` | функция `org_iri(название)` |
| Ключевое слово | `mp:keyword/{slug}` | `mp:keyword/banach-space` |
| Цитируемая работа с DOI | `mp:work/doi-{slug(doi)}` | `mp:work/doi-10-1134-s0001434619010012` |
| Цитируемая работа без DOI | `mp:work/{slug}` | функция `work_iri(фамилия, год, название)` |
| Журнал | `mp:platform/{slug}` | `mp:platform/matematicheskie-zametki`, `mp:platform/arxiv` |
| Запуск извлечения | `mp:run/{student}/{stage}-{yyyymmddHHMM}` | `mp:run/student-07/stage04-202611201530` |

`doc_id` выдаёт руководитель, он уникален во всём корпусе группы, поэтому IRI статей у разных студентов
не пересекаются. Понятия, именованные утверждения, ключевые слова, журналы и цитируемые работы
пересекаются намеренно: их IRI вычисляется общей функцией, и один объект из разных наборов получает
один IRI. Статья корпуса и её упоминание в списке литературы другой статьи связываются по DOI
(модуль 6 записывает DOI цитируемых работ, модуль 1 — DOI самой статьи).

IRI персоны строится из фамилии и инициалов, поэтому однофамильцы с одинаковыми инициалами совпадают, а
одного человека с разной записью имени («A. B. Ivanov», «Иванов А. Б.») модель разносит в разные IRI.
Отождествление авторов по адресу электронной почты, ORCID и организации — задача модуля 1 (вариант 1).

### Общий модуль `mathkg/common.py`

Модуль `mathkg/common.py` выдаётся всем и не меняется. Если функция ошибается на каком-то имени, ошибка
записывается в отчёт и исправляется руководителем централизованно, иначе графы разойдутся. Запуск
`python -m mathkg.common` печатает самопроверку. Функции: `normalize_name` (ключ понятия: леммы
значимых слов в алфавитном порядке, для русского — `pymorphy3`, для английского — приведение к
единственному числу), `slug`, `concept_iri`, `statement_iri`, `person_iri`, `org_iri`, `platform_iri`,
`doi_work_iri`, `work_iri`, `doc_iri`.

Сортировка лемм делает ключ независимым от порядка слов: «пространства Соболева» и «Соболева
пространство» дают один ключ. Ключ служит только идентификатором и бывает некрасив («неравенство
Коши — Буняковского» → «буняковского коши неравенство»: фамилия «Буняковского» словарю незнакома и
остаётся в родительном падеже); имя для показа хранится в `scilibreco:hasName` и `rdfs:label`. Русское и
английское название одного понятия («банахово пространство», «Banach space») дают разные ключи; их
связь устанавливает модуль 9 (вариант 9).

## 3. Пример: статья в графе

Условная статья (пример составлен для пояснения модели):

> УДК 517.98. MSC 46B20. **О дифференцируемости нормы в банаховых пространствах.** А. Б. Иванов,
> Московский государственный университет имени М. В. Ломоносова. Аннотация. Доказано, что …
> Ключевые слова: банахово пространство, дифференцируемость по Фреше. … **Теорема 2.1.** *Если
> пространство X рефлексивно, то …* **Доказательство.** По лемме 1.3 и неравенству (1.2) … □
> … Список литературы: [7] Diestel J. Geometry of Banach spaces. Springer, 1975.

Фрагмент графа (IRI экземпляров записаны полностью; префикс `mp:` в Turtle неудобен, потому что
локальные имена содержат `/`):

```turtle
@prefix moc: <https://w3id.org/mocassinplus/ontology#> .
@prefix scilibreco: <https://scilib.ai/ontology/scilibreco#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@base <https://w3id.org/mocassinplus/resource/> .

<doc/A04571> a moc:Document ;
    rdfs:label "О дифференцируемости нормы в банаховых пространствах"@ru ;
    scilibreco:hasTitle "О дифференцируемости нормы в банаховых пространствах" ;
    scilibreco:hasLanguage "ru" ;
    scilibreco:hasPublicationYear 2019 ;
    scilibreco:hasUDC "517.98" ;
    moc:hasMSCCode "46B20" ;
    scilibreco:hasAuthor <person/ivanov-a-b> ;
    scilibreco:hasKeyword <keyword/banakhov-prostranstvo> ;
    scilibreco:hasConcept <concept/banakhov-prostranstvo> ;
    scilibreco:containsStatement <doc/A04571/st-0004> ;
    moc:hasSegment <doc/A04571/title> , <doc/A04571/abstract> , <doc/A04571/st-0004> .

<person/ivanov-a-b> a scilibreco:Author ;
    scilibreco:hasName "А. Б. Иванов" ;
    scilibreco:hasNormalizedName "иванов а б" ;
    scilibreco:hasAffiliation <org/gosudarstvennyy-imya-lomonosov-m-moskovskiy-universitet> .

<doc/A04571/st-0004> a moc:Theorem ;
    moc:hasLabel "Теорема 2.1" ;
    moc:hasNumber "2.1" ;
    moc:hasText "Если пространство X рефлексивно, то …" ;
    moc:hasPageNumber 5 ;
    moc:hasStartOffset 10412 ;
    moc:hasEndOffset 10630 ;
    moc:isPartOf <doc/A04571/p-0031> ;
    moc:provedBy <doc/A04571/prf-0001> ;
    moc:mentionsConcept <concept/banakhov-prostranstvo> ;
    moc:hasExtractionMethod "rule" ;
    moc:hasConfidence 0.95 ;
    moc:generatedBy <run/student-02/stage04-202611201530> .

<doc/A04571/prf-0001> a moc:Proof ;
    moc:proves <doc/A04571/st-0004> ;
    moc:usesLemma <doc/A04571/st-0002> ;
    moc:refersToFormula <doc/A04571/f-0003> ;
    moc:hasText "По лемме 1.3 и неравенству (1.2) …" .

<doc/A04571/ref-07> a moc:ReferenceEntry ;
    moc:hasNumber "7" ;
    moc:hasText "Diestel J. Geometry of Banach spaces. Springer, 1975." ;
    moc:isPartOf <doc/A04571/bib> .

<concept/banakhov-prostranstvo> a moc:MathematicalConcept ;
    rdfs:label "банахово пространство"@ru ;
    scilibreco:hasName "банахово пространство" ;
    scilibreco:hasNormalizedName "банахов пространство" .
```

Связь `moc:usesLemma` идёт от доказательства к лемме: в тексте доказательства сказано «по лемме 1.3»,
номер «1.3» сопоставляется с `moc:hasNumber` леммы той же статьи. Связь `moc:refersToFormula` получена
так же по номеру формулы «(1.2)».

## 5. Формат результата модуля

Модуль получает статью после base (`Doc`) и результаты модулей, от которых зависит (`Context`), и
возвращает `Facts` — фрагменты и связи. Типы описаны в `mathkg/model.py`.

**Doc** (base): `doc_id`, `lang`, `text` — очищенный текст статьи; `pages`, `paragraphs`,
`sentences` — отрезки `[start, end)` с номером страницы; `styled` — отметки шрифта (`bold`,
`italic`, `math`); `formulas` — выключные формулы (`text` из PDF, `number`, `bbox`, `latex`);
`links` — гиперссылки PDF с именованной целью (`cite.Diestel75`, `equation.2.3`); `footnotes`;
`first_page_lines` — строки первой страницы с кеглем и начертанием; `meta` — качество текстового
слоя и метаданные PDF.

**Fragment** (отрезок текста с классом онтологии): `id` (локальный, префикс модуля, см. §2), `cls`
(`moc:Theorem`), `start`, `end`, `number` («2.1»), `label` («Теорема 2.1 (Банах)»), `page`,
`method` (`rule` | `model` | `llm` | `manual`), `confidence` (0–1), `attrs` (литералы фрагмента,
например `{"scilibreco:isDisplayFormula": false}`).

**Relation** (тройка): `subj`, `pred`, `obj` — локальный id фрагмента статьи (`st-0004`, `p-0031`,
`f-0012`), полный IRI или имя с префиксом (`mp:concept/…`, `moc:Theorem`); `literal` и `datatype`
для литералов; `method`, `confidence`; `start`, `end` — где в тексте найдено основание связи.

Правила контракта (их проверяет `mathkg.check`):

1. позиции фрагментов лежат внутри `Doc.text`, `start < end`;
2. класс фрагмента и свойство связи объявлены в онтологиях;
3. локальный id ссылается на фрагмент своего модуля, модуля-зависимости или base (`p-`, `f-`,
   `title`, `abstract`, `keywords`, `bib`);
4. `method` из списка, `confidence` в [0, 1];
5. среднее время модуля на статью — не больше 2 с (языковая модель — только на отобранных
   фрагментах).

Результаты прогона хранятся по файлу на модуль и статью: `facts/{инструмент}/{doc_id}.json`.
`pipeline.export_jsonl` сводит их в `facts/fragments.jsonl` и `facts/relations.jsonl` для анализа и
векторизации. Граф набора пишется в N-Triples (`mathkg.to_rdf`).

Ручной эталон модуля — `gold/mNN.jsonl`, по строке на объект, с дословной цитатой вместо позиций:

```json
{"doc_id": "A04571", "cls": "moc:Theorem", "number": "2.1", "quote": "Теорема 2.1. Пусть X — рефлексивное"}
{"doc_id": "A04571", "pred": "moc:proves", "subj_quote": "Доказательство. По лемме 1.3", "obj_quote": "Теорема 2.1. Пусть X"}
```

## 7. Проверки графа перед загрузкой

Скрипт проверки (этап 7) выполняет простые запросы к локальному графу и печатает число нарушений:

1. у каждого сегмента есть `moc:segmentOf` или `moc:isPartOf`;
2. у каждого объекта есть класс из онтологии;
3. у каждого `moc:Definition` есть `moc:defines`;
4. у каждого `moc:Proof` есть `moc:proves`, и его объект — утверждение той же статьи;
5. у каждой формулы есть `moc:hasPlainText` или `moc:hasLatexSource` и `moc:occursIn`;
6. у каждого извлечённого объекта есть `moc:hasExtractionMethod`;
7. литералы `moc:`/`scilibreco:` записаны без метки языка, `rdfs:label` — с меткой;
8. все IRI экземпляров начинаются с `https://w3id.org/mocassinplus/resource/`.
