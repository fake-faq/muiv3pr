# Общая часть: пакет mathkg

Общая часть практики — пакет `mathkg` в папке `mathkg/` и онтологии в папке `ontology/`. Пакет
превращает научную статью в PDF в текст с разметкой, запускает на нём десять модулей извлечения,
проверяет и оценивает их результаты, переводит результаты в граф RDF и отдаёт модули агенту как
инструменты. Работа каждого студента встраивается в пакет: студент заменяет базовую версию своего
модуля своей, и с этого момента его версией пользуются вся группа, граф и агент.

Пакет держится на трёх соглашениях.

* **Один текст статьи на всех.** Все модули работают с одним объектом `Doc`, который строит общая
  основа `base`. Позиции фрагментов считаются в символах одного и того же текста, поэтому находки
  разных модулей и разных студентов можно сопоставлять и связывать.
* **Один контракт результата.** Модуль возвращает фрагменты и связи в общем формате (`Facts`)
  с классами и свойствами онтологий MocassinPlus v2 и SciLibReco. Контракт проверяется
  автоматически перед каждой сборкой.
* **Одни правила IRI.** Понятие, именованная теорема, журнал, цитируемая работа получают IRI из
  общей функции, поэтому один объект из наборов разных студентов становится одной вершиной графа.

Демонстрация всех частей пакета на одной статье — блокнот `notebooks/00_Общая_часть.ipynb`.

## 1. Путь статьи

```
PDF ──base──▶ Doc ──модули m01…m10──▶ Facts ──to_rdf──▶ граф N-Triples ──▶ GraphDB, SPARQL
               │                        │
               │                        ├──check / evaluate──▶ проверка контракта, F1 по эталону
               │                        └──векторы e5, FAISS──▶ поиск «вектор + граф»
               └──────── registry.agent_tools ──▶ инструменты агента, MCP-сервер
```

| Шаг | Вызов | Результат |
|---|---|---|
| PDF → Doc | `base.load_doc(pdf, doc_id)`, по набору — `base.build_corpus(index.csv, pdf/, base/)` | `base/{doc_id}.json`, сводка `base/docs.jsonl` |
| Модули на наборе | `pipeline.setup(student_modules=…)`, `pipeline.run_corpus(base/, facts/)` | `facts/{инструмент}/{doc_id}.json` |
| Проверка контракта | `check.check_module(инструмент, …)`, `check.build_report(…)` | таблица: прошёл ли модуль, ошибки, число находок, время |
| Оценка | `evaluate.evaluate(инструмент, gold/mNN.jsonl, base/, facts/)` | точность, полнота, F1 по классам и связям; пропуски и лишние находки |
| Граф | `to_rdf.corpus_to_ntriples(base/, facts/, graph.nt, 'student-NN')` | N-Triples для загрузки в GraphDB |
| Агент | `registry.agent_tools(загрузчик статьи)` | инструменты в формате шаблона чата `transformers` и MCP |

`build_corpus` и `run_corpus` продолжают работу с места обрыва: после перезапуска сеанса Colab уже
обработанные статьи не пересчитываются.

## 2. Общая основа base: PDF → Doc

`base` читает PDF библиотекой PyMuPDF и собирает статью:

* строки со шрифтом и кеглем, порядок колонок, удаление колонтитулов и номеров страниц;
* склейка переносов, вынос сносок в `doc.footnotes`;
* абзацы и предложения (русский и английский текст);
* отметки шрифта: полужирный, курсив, математический шрифт;
* выключные формулы с номерами «(2.3)», замена символов шрифта Symbol на Юникод;
* внутренние гиперссылки PDF статей из LaTeX: текст ссылки и её цель (`theorem.2.1`,
  `equation.2.3`, `cite.Banach32`);
* проверка текстового слоя: сканы и PDF со сломанной кодировкой отмечаются и исключаются;
* распознавание LaTeX выключных формул по картинке (`recognize_formulas`, модель pix2tex, нужен GPU).

Поля `Doc`:

| Поле | Что хранит |
|---|---|
| `doc_id`, `lang` | номер статьи в наборе, язык (`ru` / `en`) |
| `text` | очищенный текст статьи одной строкой |
| `pages`, `paragraphs`, `sentences` | отрезки `[start, end)` текста с номером страницы (`Span`) |
| `styled` | отметки шрифта: `Span` с `kind` = `bold`, `italic`, `math` |
| `formulas` | выключные формулы (`Formula`): текст из PDF, номер, страница, рамка `bbox`, LaTeX |
| `links` | гиперссылки PDF (`Link`): позиция текста ссылки, цель, страница цели |
| `footnotes` | тексты сносок |
| `first_page_lines` | строки первой страницы с кеглем и начертанием (для метаданных) |
| `meta` | файл, число страниц, качество текстового слоя, метаданные PDF |

Абзац номер k статьи — сегмент `p-000k` в графе, выключная формула — `f-000k`.

## 3. Контракт модуля

Модуль — функция с декоратором `@tool`. Она получает `Doc` и `Context` (результаты модулей, от
которых зависит, на той же статье) и возвращает `Facts`.

```python
from mathkg.model import Context, Doc, Facts
from mathkg.registry import tool

@tool(name="extract_proofs", module="m07", requires=("extract_statements",),
      produces=("moc:Proof", "moc:proves", "moc:provedBy"), author="Фамилия И. О.")
def extract_proofs(doc: Doc, ctx: Context) -> Facts:
    """Описание для агента: что находит инструмент и что возвращает."""
    facts = Facts("extract_proofs", doc.doc_id)
    statements = ctx.facts("extract_statements").fragments      # результат модуля 3
    ...
    f = facts.add_fragment(id="prf-0001", cls="moc:Proof", start=..., end=..., page=...,
                           method="rule", confidence=0.9)
    facts.add(f.id, "moc:proves", statements[0].id)
    return facts
```

* **Fragment** — отрезок текста с классом онтологии: `id` (префикс модуля и номер: `st-0004`,
  `prf-0002`), `cls`, `start`, `end`, `number`, `label`, `page`, `method` (`rule`, `model`, `llm`,
  `manual`), `confidence` от 0 до 1, `attrs` (литералы фрагмента).
* **Relation** — тройка: `subj`, `pred`, `obj`; субъект и объект — локальный id фрагмента
  (`st-0004`, `p-0031`, `f-0012`), полный IRI или имя с префиксом (`mp:concept/…`); `literal` и
  `datatype` для литералов; `method`, `confidence`; `start`, `end` — где в тексте найдено основание
  связи.
* **Facts** — результат модуля на статье: списки фрагментов и связей; `add_fragment`, `add`, `find`.

Правила контракта, которые проверяет `mathkg.check`:

1. позиции фрагментов лежат внутри `doc.text`, начало меньше конца;
2. класс фрагмента и свойство связи объявлены в онтологиях;
3. локальный id ссылается на фрагмент своего модуля, модуля-зависимости или base;
4. метод из списка, уверенность в отрезке [0, 1];
5. среднее время модуля на статью не больше 2 с.

Метод и уверенность попадают в граф как свойства происхождения факта (`moc:hasExtractionMethod`,
`moc:hasConfidence`); по ним агент различает факт, найденный правилом, и факт, предложенный
моделью.

## 4. Десять модулей

Базовые версии всех модулей (простые правила) лежат в `mathkg/modules/` и работают с первого дня.
Вариант NN практики — модуль NN.

| Модуль | Инструмент | Зависит от | Базовая версия находит |
|---|---|---|---|
| m01 Метаданные | `extract_metadata` | — | заголовок, аннотацию, ключевые слова, авторов и e-mail, УДК, MSC, DOI, год |
| m02 Структура | `extract_structure` | — | разделы с номерами и типами (введение, результаты, заключение), подписи |
| m03 Утверждения | `extract_statements` | — | теоремы, леммы, предложения, следствия, гипотезы с номерами и метками |
| m04 Определения | `extract_definitions` | — | определения (блоки и внутри абзаца) и понятия, которые они вводят |
| m05 Формулы | `extract_formulas` | — | уравнения среди выключных формул, нормализованную запись, строчные формулы |
| m06 Литература | `extract_bibliography` | — | список литературы, записи с номерами, DOI и годом |
| m07 Доказательства | `extract_proofs` | m03 | доказательства и связь каждого с утверждением (`moc:proves`) |
| m08 Ссылки и зависимости | `extract_references` | m02, m03, m04, m06, m07 | ссылки на утверждения, формулы, разделы, литературу; зависимости доказательств (`moc:usesLemma`, `moc:usesTheorem`) |
| m09 Понятия | `extract_concepts` | m01, m04 | упоминания понятий в абзацах, именованные результаты («теорема Банаха — Штейнгауза») |
| m10 Предметные области | `classify_topics` | m01 | разделы arXiv статьи по кодам MSC и УДК |

Зависимость задаёт только порядок запуска. Модуль второго и третьего слоя с первого дня работает
на результатах базовых версий модулей, от которых зависит, поэтому никто никого не ждёт. Что
добавляет к базовой версии каждый вариант — в `ЗАДАНИЯ.md`.

## 5. Свой модуль вместо базовой версии

Студент кладёт файл `mNN_<название>.py` в папку `modules/` репозитория группы и сдаёт его запросом
на слияние своей ветки в `main` (`ИНСТРУКЦИЯ_git.md`). В файле — функция с декоратором `@tool` и тем
же `name`, что у базовой версии. `pipeline.setup(student_modules=папка)`
регистрирует базовые версии, затем файлы из папки; студенческая версия заменяет базовую в прогоне,
в графе и у агента.

* Менять нельзя: имя инструмента, `requires`, формат результата и префиксы id — от них зависят
  другие модули.
* Можно всё внутри функции: правила, модели Hugging Face, языковую модель, вызов базовой версии и
  доработку её результата (`from mathkg.modules.m04_definitions import extract_definitions as base_version`).
* Шаблон пустого модуля — `mathkg/modules_template/mNN_template.py`; образец модуля с двумя
  ступенями (правила и классификатор) — `mathkg/modules_template/m04_model_example.py`.
* Пересчёт своего модуля на наборе — `run_corpus(base/, facts/, redo=[инструмент])`; зависящие от
  него модули пересчитываются вместе с ним.

Помощники для правил — `mathkg/modules/_util.py`: `header_re` (заголовки блоков «Теорема 2.1.»),
`is_bold`, `italic_share`, `paragraph_at`, `numbered`.

## 6. Модели Hugging Face

Модули берут модели из общего кэша `mathkg/models.py`: модель загружается один раз за сеанс, и все
модули получают одну её копию. Модуль сам модели не загружает.

| Вызов | Модель по умолчанию | Для чего |
|---|---|---|
| `get_sentence_model(name)` | `intfloat/multilingual-e5-base` | векторы абзацев и фрагментов, классификатор на векторах, поиск |
| `get_pipeline(task, model)` | например `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli` | zero-shot классификация, NER, классификация текста |
| `get_llm(name)`, `generate(prompts)` | `Qwen/Qwen2.5-1.5B-Instruct` | извлечение языковой моделью на отобранных фрагментах |

Без GPU модели работают на процессоре; на GPU кодировщик и языковая модель загружаются в
половинной точности.

## 7. Инструменты агента

Каждый модуль извлечения — инструмент агента. `registry.agent_tools(загрузчик)` отдаёт список
инструментов: имя, описание (докстринг функции модуля), JSON-схема параметров и функция вызова.
Инструмент извлечения принимает `doc_id`, сам загружает статью и возвращает сжатый результат:
полные IRI, класс, метод, уверенность и начало текста каждого фрагмента. Кроме инструментов
извлечения в реестре есть инструменты запросов, объявленные декоратором `@query_tool`:

* встроенные `get_article_text(doc_id, start_paragraph, n_paragraphs)` и
  `find_in_article(doc_id, phrase)` — чтение текста статьи (папка base набора задаётся переменной
  окружения `KG_BASE_DIR`);
* студенческие инструменты запросов к графу и поиску (этапы 8–10), файлы `qNN_*.py`.

Агент выбирает инструмент по описанию, поэтому докстринг модуля пишется для читателя-модели: что
находит инструмент и что возвращает.

## 8. Граф

`to_rdf` пишет статьи и результаты модулей в N-Triples по модели данных MocassinPlus v2
(`moc:`, `https://w3id.org/mocassinplus/ontology#`) и SciLibReco (`scilibreco:`,
`https://scilib.ai/ontology/scilibreco#`). В граф попадают абзацы, на которые ссылаются модули;
каждый факт несёт происхождение: запуск извлечения `moc:ExtractionRun`, инструмент, метод,
уверенность, позиции и страницу.

IRI экземпляров строятся функциями `mathkg/common.py` в пространстве имён
`mp:` = `https://w3id.org/mocassinplus/resource/`:

| Объект | IRI |
|---|---|
| статья | `mp:doc/{doc_id}` |
| абзац, формула, фрагмент модуля | `mp:doc/{doc_id}/p-0031`, `…/f-0012`, `…/st-0004`, `…/prf-0005` |
| понятие | `mp:concept/{slug}` — `concept_iri(имя)` |
| именованное утверждение | `mp:statement/{slug}` — `statement_iri(имя)` |
| автор, организация, журнал | `person_iri(фамилия, инициалы)`, `org_iri(название)`, `platform_iri(журнал)` |
| цитируемая работа | `doi_work_iri(doi)` или `work_iri(фамилия, год, название)` |

Ключ `slug` строится из нормализованного имени (`normalize_name`: леммы слов, единственное число,
одинаковая запись диакритики и сокращений). Поэтому «банаховы пространства» и «банахово
пространство» из разных статей дают одно понятие `mp:concept/…`.

Граф студента загружается в GraphDB в именованный граф
`https://w3id.org/mocassinplus/graph/student-NN`; онтологии лежат в графе
`https://w3id.org/mocassinplus/graph/tbox`.

## 9. Ручной эталон

Качество модуля измеряется по ручному эталону `gold/mNN.jsonl` на 10 статьях общего тестового
набора: по строке на объект, с дословной цитатой начала фрагмента вместо позиций.

```json
{"doc_id": "T0003", "cls": "moc:Theorem", "number": "2.1", "quote": "Теорема 2.1. Пусть X — рефлексивное"}
{"doc_id": "T0003", "pred": "moc:proves", "subj_quote": "Доказательство. По лемме 1.3", "obj_quote": "Теорема 2.1. Пусть X"}
{"doc_id": "T0003", "pred": "moc:hasDOI", "subj": "doc", "value": "10.1134/S0001434619010012"}
```

Эталон перечисляет все объекты своего класса в каждой статье. Цитату надёжнее копировать из текста
base: в PDF буквы и знаки бывают набраны похожими символами Юникода (знак ома вместо греческой Ω),
и набранная с клавиатуры цитата не найдётся.

## 11. Известные ограничения base

* Пределы сумм и интегралов иногда отделяются от своей формулы; числа в таблицах и строки кода
  иногда принимаются за выключные формулы.
* Скан с распознанным текстовым слоем проверку проходит, и шум распознавания («[0, l]2 —•»)
  остаётся в тексте.
* Текст гиперссылки PDF определяется по строке шрифта и бывает неточным («2.4)» вместо «2.4»).
* Сноски хранятся в `doc.footnotes` без позиций в тексте.
* Модуль 10 и словарь понятий модуля 9 строят связи по всему набору и пишутся отдельным файлом
  N-Triples (этап 7).

Замечания к base студенты записывают в задачи (Issues) репозитория группы с меткой `base`;
руководитель исправляет base между сборками.
