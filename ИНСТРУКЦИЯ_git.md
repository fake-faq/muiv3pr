# Работа с репозиторием группы

Вся работа студентов сдаётся в этот репозиторий на GitHub: модули, эталоны, инструменты запросов,
блокноты этапов с выводами, отчёты. Данные в репозиторий не кладутся: свой набор из 1000 статей и
результаты его обработки лежат в личной папке `practice2026/` на Google Drive, общий тестовый
набор — в общей папке `kg_data/` на Drive руководителя (только чтение).

| Где | Что лежит | Кто пишет |
|---|---|---|
| репозиторий, ветка `main` | принятая работа группы: общий код, модули, эталоны, блокноты этапов, отчёты сборок | руководитель (принимает запросы на слияние) |
| репозиторий, ветка `student-NN` | своя работа до приёма | студент NN |
| Drive, `practice2026/` | свой набор (`pdf/`, `index.csv`), `base/`, `facts/`, папки этапов `stageNN/` с отчётом и результатами | студент |
| Drive, `kg_data/test_set/` | общий тестовый набор: `pdf/`, `base/`, `facts_base/`, результаты сборок | руководитель |

## 1. Подготовка (один раз)

1. **Аккаунт GitHub.** Студент сообщает руководителю свой логин и принимает приглашение в
   репозиторий (письмо от GitHub или страница репозитория).
2. **Токен для Colab.** На GitHub: Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token. Repository access — Only select repositories →
   `kg-practice-2026` (если репозиторий принадлежит организации, в поле Resource owner выбирается
   она); Permissions → Repository permissions → Contents — Read and write; срок действия — до конца
   практики. Токен показывается один раз, его сразу копируют.
3. **Секрет Colab.** В любом блокноте Colab: значок ключа на левой панели → Add new secret, имя
   `GITHUB_TOKEN`, значение — токен; переключатель Notebook access включается в каждом блокноте,
   где выполняется ячейка подключения. Токен не вставляют в код и не публикуют: с ним можно писать
   в репозиторий от имени студента.
4. **Google Drive.** Папку `kg_data`, которую открыл руководитель, добавляют в «Мой диск» (правая
   кнопка → Упорядочить → Добавить ярлык → Мой диск). Свой набор, переданный руководителем, кладут в
   папку `practice2026/` на своём Диске: `practice2026/pdf/` и `practice2026/index.csv`.

Чужие файлы студент не меняет. Ячейка сдачи отправляет только свои файлы из этой таблицы.

## 3. Каждый сеанс

1. **Блокнот этапа.** Блокнот открывается из репозитория в Colab: File → Open notebook → GitHub,
   репозиторий группы, файл `notebooks/stageNN_….ipynb`. Своя копия сохраняется на Drive:
   File → Save a copy in Drive, имя `stageNN_фамилия.ipynb` (например `stage03_ivanov.ipynb`).
   Дальше работа идёт в этой копии; в следующем сеансе её открывают с Drive.
2. **Ячейка подключения** — первая ячейка блокнота. В ней студент один раз заполняет три строки:

   ```python
   STUDENT = 'student-07'                     # ← свой номер: вариант 7 — student-07
   MY_MODULE = 'm07'                          # ← свой модуль: вариант 7 — m07
   SURNAME = 'ivanov'                         # ← фамилия латиницей строчными буквами
   ```

   Ячейка подключает Drive, клонирует репозиторий в `/content/kg-practice-2026`, переключается на
   свою ветку `student-NN` (при первом запуске создаёт её от `main`) и подтягивает в неё всё, что
   руководитель уже принял в `main`, — свежий общий код и модули соседей. После неё в блокноте
   доступны `KG` (клон репозитория), `WORK` (личная папка), `TEST` (тестовый набор) и объект `repo`.
3. **Работа.** Свой модуль правится в `KG + '/modules/mNN_*.py'` (редактор файлов Colab или ячейка
   `%%writefile`), эталон пишется в `KG + '/gold/mNN.jsonl'`, результаты этапа — в
   `WORK + '/stageNN/'`.
4. **Не потерять работу.** Папка `/content/kg-practice-2026` исчезает с концом сеанса Colab (в том
   числе после простоя около 90 минут). Всё, что сделано в ней, отправляется в свою ветку до конца
   сеанса, даже незаконченное:

   ```python
   repo.submit('Этап 3: черновик правил')       # своя ветка на GitHub; запрос на слияние не нужен
   ```

   Данные на Drive (`practice2026/`) сохраняются сами.

## 4. Сдача этапа

1. Отчёт `REPORT.md` кладётся в папку этапа на Drive: `practice2026/stageNN/REPORT.md`.
2. Блокнот сохраняется (Ctrl+S).
3. Выполняется последняя ячейка блокнота — ячейка сдачи:

   ```python
   STAGE = 3
   repo.save_notebook(f'stage{STAGE:02d}_{SURNAME}.ipynb', STAGE)   # блокнот с выводами → students/NN_фамилия/
   repo.collect(f'{WORK}/stage{STAGE:02d}', STAGE)                  # отчёт и небольшие результаты этапа
   repo.submit(f'Этап {STAGE}: {SURNAME}')                         # свои файлы → ветка student-NN
   ```

   `collect` копирует из папки этапа текстовые файлы и картинки до 1 МБ (отчёт, таблицы CSV, запросы
   `.rq`, журналы) и называет файлы, которые остались на Drive (векторы, индексы, графы `.nt`).
4. Ячейка печатает ссылку вида `https://github.com/…/compare/main...student-07`. По ссылке
   открывается запрос на слияние (Create pull request) с заголовком «Этап N: фамилия»; отметки в
   шаблоне запроса заполняются.
5. Этап считается сданным в срок, если запрос на слияние открыт до начала встречи-срока. Руководитель
   оставляет замечания в запросе; исправления студент вносит в том же блокноте и снова выполняет
   ячейку сдачи — запрос обновляется сам, новый открывать не нужно.
6. После приёма работа попадает в `main`, и у всех остальных студентов она появляется при
   следующем запуске ячейки подключения: так модуль студента начинает работать в библиотеке группы.

Сборки 1 и 2 (встречи 5 и 7) идут по `main`: в сборку попадают модули из принятых запросов на
слияние. Состояние `main` на момент сборки отмечается метками `build-1` и `build-2`. После сборки 2
запросы с изменениями `modules/` не принимаются, и этап 7 все выполняют с одной библиотекой.

## 5. Замечания к общему коду и модулям соседей

* Ошибка base или общего кода — задача (Issues → New issue) с меткой `base`: в заголовке коротко,
  что не так; в тексте — `doc_id`, страница, что видно, чего ожидалось. Перед записью стоит
  проверить, нет ли уже такой задачи, и при совпадении добавить к ней свой пример.
* Ошибка модуля соседа — задача с меткой модуля (`m01`…`m10`). Автор модуля отвечает в ней и
  закрывает её ссылкой на свой запрос на слияние с исправлением.
* Чужой файл у себя не исправляют: правка не попадёт в сдачу (ячейка сдачи её назовёт и пропустит)
  и при следующем слиянии с `main` вызовет конфликт.

## 6. Что не кладётся в репозиторий

PDF статей, результаты base и модулей (`base/`, `facts/`), графы `.nt`, векторы и индексы, кэш
ответов языковой модели, большие таблицы — всё это остаётся в `practice2026/` на Drive. Токен
GitHub, пароли GraphDB и ключи хранятся только в секретах Colab. Список исключений — `.gitignore`;
ячейка сдачи отправляет только свои файлы из раздела 2.

## 7. Работа на своём компьютере

```bash
git clone https://github.com/<организация>/kg-practice-2026.git
cd kg-practice-2026
git checkout student-07 || git checkout -b student-07     # своя ветка
git pull origin main                                     # принятая работа группы
# ... правка своих файлов ...
git add modules/m07_proofs.py gold/m07.jsonl students/07_ivanov
git commit -m "Этап 3: ivanov"
git push -u origin student-07                            # затем запрос на слияние на GitHub
```

Тот же объект `repo` работает и вне Colab: `Repo(путь_к_клону, 'student-07', 'm07', 'ivanov')`.

## 8. Если что-то не так

| Признак | Причина и что делать |
|---|---|
| ячейка подключения: `Authentication failed`, `Repository not found` | секрет `GITHUB_TOKEN` не создан, у блокнота нет к нему доступа (Notebook access), токен просрочен или выдан не на этот репозиторий; приглашение в репозиторий не принято |
| `repo.submit`: `Permission denied`, `403` | у токена нет права Contents — Read and write |
| `Слияние с main не удалось` | в своей ветке изменён общий или чужой файл; его возвращают к версии группы: `repo.git('checkout', 'origin/main', '--', 'путь')`, затем снова `repo.start()` |
| `нет файла …/Colab Notebooks/stageNN_….ipynb` | копия блокнота на Drive называется иначе или не сохранена: имя в ячейке сдачи должно совпадать с именем копии |
| работа за сеанс пропала | сеанс закончился до `repo.submit`; данные на Drive при этом целы, код и эталон восстанавливаются из последней отправки |
| в запросе на слияние видны чужие файлы | они попали в ветку командами git в обход `repo.submit`; руководитель подскажет, как их убрать |
| `TEST` не существует | ярлык `kg_data` не добавлен в «Мой диск» |
