# Вариант 05. Модуль m05: формулы и уравнения

## Что делает модуль

Модуль работает с формулами статьи. Выключные формулы, их номера, координаты и LaTeX находит общая
основа base; модуль 5 решает, какие из них уравнения, записывает нормализованную запись, находит
строчные формулы-отношения внутри текста («x_n → 0», «f ∈ L²(Ω)»), выделяет переменные с их
описаниями («где u — температура») и даёт формуле имя по контексту («уравнение теплопроводности»,
«неравенство Гёльдера»). Формулы нужны графу как объекты, на которые ссылается текст («в силу
(2.3)»), поиску — как объекты, найденные по описанию, и агенту — для ответов «какое уравнение
рассматривается в статье».

Инструмент в реестре — `extract_formulas`. Модуль зависит только от base. Модуль 8 разрешает
ссылки на формулы по номерам, которые нашла base; имена и типы формул из модуля 5 видны в карточке
ссылки.

## Базовая версия

Base (`mathkg/base`) выделяет выключную формулу как строку с высокой долей математических символов
или математических шрифтов (CMMI, CMSY, STIX, Cambria Math), с отступом от края текста или номером
«(2.3)» у правого края; номер отдельной строкой присоединяется к формуле той же высоты. Функция
`recognize_formulas` вырезает формулу по координатам и распознаёт LaTeX моделью pix2tex.

Код `mathkg/modules/m05_formulas.py`:

* выключная формула получает класс `moc:Equation`, если в её записи (LaTeX или текст из PDF) есть
  «=» и нет знаков неравенства;
* нормализованная запись — пробелы вокруг знаков, без хвостовой пунктуации
  (`moc:hasNormalizedText`);
* формула связана с абзацем, перед которым или в котором стоит (`moc:occursIn`,
  `moc:containsExpression`);
* строчная формула (`if-NNNN`) — отрезок математического шрифта длиной от трёх символов со знаком
  отношения (=, <, ≤, ∈, ⊂, →); одиночные обозначения (x, f, n) не записываются.

Слабые места (по коду и тестовому прогону):

* **ложные формулы base:** числа из таблиц («22.4×», «1.47×») и строки кода принимаются за
  выключные формулы; модуль 5 удалить объект base не может, он может только не присвоить ему класс
  уравнения и сообщить о ложных формулах руководителю;
* **разорванные формулы:** пределы суммы «i=1» и знаменатели дробей иногда отделяются от формулы в
  отдельную формулу или абзац;
* **класс уравнения:** «=» внутри перечисления («x = 1, 2, …») или определения («:=») тоже даёт
  `moc:Equation`;
* **LaTeX** есть только после запуска `recognize_formulas`; без него нормализованная запись — это
  текст из PDF с потерянными индексами;
* **имена, переменные, описания переменных** не извлекаются.

## Классы и свойства

| | Базовая версия | Добавляет студент |
|---|---|---|
| Выключные формулы (base, `f-NNNN`) | `moc:Formula` с `moc:hasPlainText`, `moc:hasNumber`, `moc:hasLatexSource`, `scilibreco:isDisplayFormula` (пишет base); модуль: `rdf:type moc:Equation`, `moc:hasNormalizedText`, `moc:occursIn`, `moc:containsExpression` | имя формулы `scilibreco:hasName`, `scilibreco:hasNamingMethod` («rule», «llm»), `scilibreco:hasNamingConfidence`; `scilibreco:hasSourceForm` и `scilibreco:hasNotationFormat` («latex» или «plain») |
| Строчные формулы (`if-NNNN`) | `moc:Formula` с `scilibreco:isDisplayFormula false`, `moc:occursIn` | отсев ложных, `moc:hasNormalizedText` |
| Переменные | — | `moc:Variable` (`var-NNNN`) — обозначение в тексте «где u — …»; формула `moc:containsExpression` переменная; переменная `scilibreco:hasName` («температура») |
| Символы | — | `moc:Symbol` для специальных знаков с описанием («∆ — оператор Лапласа») |

Домены соблюдены: `scilibreco:hasNamingMethod`, `scilibreco:hasNamingConfidence`,
`scilibreco:hasSourceForm`, `scilibreco:hasNotationFormat` определены для
`moc:MathematicalExpression`, а `moc:Formula`, `moc:Variable`, `moc:Symbol` — его подклассы;
`moc:containsExpression` идёт от сегмента документа к математическому выражению.

Замечание к модели. В онтологиях нет способа пометить объект base как ошибочный (таблица, принятая
за формулу). Модуль только не добавляет такой формуле своих троек; удаление ложных формул — правка
base, которую делает руководитель по списку от студента.

## Работа по этапам

**Этап 1.** Студент запускает base на своём наборе, затем `recognize_formulas` на выключных формулах
20 статей тестового набора (GPU T4), и сравнивает текст из PDF с распознанным LaTeX: что теряется в
текстовом слое (индексы, дроби, корни, матрицы).

**Этап 2.** Студент смотрит на отметки `math` (`Doc.styled`) и на выключные формулы base в 20
статьях и составляет список ложных формул по видам: таблицы, код, номера страниц, подписи осей.
Гиперссылки PDF с целями `equation.2.3` (`Doc.links`) показывают, где стоит формула с номером «(2.3)»:
по ним студент проверяет номера, которые присвоила base. Первые правила: уравнение — знак «=» вне
«:=» и вне перечислений; «где …», «where …» после формулы открывают описание переменных.

**Этап 3.** Версия «правила». Студент:

* уточняет класс уравнения: «=» на верхнем уровне записи, без «:=» и без шаблона «x = 1, 2, …»;
* отбрасывает строчные формулы, совпадающие с номерами ссылок «(2.3)» и с годами;
* выделяет переменные из конструкций «где u(x, t) — температура, k — коэффициент
  теплопроводности» и «where u denotes the velocity»: обозначение → `moc:Variable`, описание →
  `scilibreco:hasName`;
* даёт имя формуле по шаблонам контекста: «уравнение теплопроводности (2.3)», «неравенство (3.1)
  Гёльдера», «the Navier–Stokes equations (1.1)» — `scilibreco:hasNamingMethod "rule"`.

Размечается эталон.

**Этап 4.** Версия «правила + модель». Классификатор «формула или нет» для выключных формул base:
признаки — доля букв, цифр, математических знаков, наличие номера, длина, соседство с подписью
таблицы; эмбеддинг записи `intfloat/multilingual-e5-small`; логистическая регрессия. Серебряная
разметка: положительные примеры — формулы с номером, подтверждённым гиперссылкой `equation.*`;
отрицательные — строки внутри таблиц (рядом с подписью «Таблица», «Table») и строки кода (`:=`,
отступы, ключевые слова). Формулы, которые классификатор считает ложными, модуль не помечает
уравнениями и выписывает в отчёт.

**Этап 5.** Связи: формула `moc:containsExpression` переменная, формула `moc:occursIn` абзац,
статья `scilibreco:containsFormula` строчная формула. Имя формулы, совпадающее с именованным
результатом («неравенство Гёльдера»), студент сверяет с IRI `statement_iri`, который создаёт модуль 9
(`mp:statement/geldera-neravenstvo`), и сообщает автору варианта 9 об именах формул, которых нет в его
словаре.

**Этап 6.** Языковая модель даёт имя формулам с номером, у которых правила имени не нашли:
`Qwen/Qwen2.5-1.5B-Instruct` получает предложение перед формулой, текст формулы (LaTeX, если есть) и
предложение после неё и возвращает JSON `{name, confidence, variables: [{symbol, meaning}]}`. Имя
проверяется по контексту: хотя бы одно значимое слово имени должно встречаться в окрестности
формулы. Чтобы модуль укладывался в 2 с на статью, наименование оформлено отдельным инструментом
`name_formulas(doc_id)`: агент вызывает его по запросу, студент прогоняет его на 100 статьях выборки
и записывает имена с `scilibreco:hasNamingMethod "llm"`.

**Этап 7.** В графе набора студент считает выключные формулы, уравнения, формулы с именами и долю
формул с LaTeX.

**Этап 8.** Инструмент запросов `find_formula(name: str, limit: int = 10) -> list[dict]` — формулы,
имя или запись которых содержит строку, с номером, LaTeX и статьёй. Пример для «теплопроводн»:

```sparql
PREFIX moc: <https://w3id.org/mocassinplus/ontology#>
PREFIX scilibreco: <https://scilib.ai/ontology/scilibreco#>
SELECT ?f ?name ?num ?plain ?latex ?doc
WHERE {
  ?doc scilibreco:containsFormula ?f .
  ?f moc:hasPlainText ?plain .
  OPTIONAL { ?f scilibreco:hasName ?name }
  OPTIONAL { ?f moc:hasNumber ?num }
  OPTIONAL { ?f moc:hasLatexSource ?latex }
  FILTER(CONTAINS(LCASE(STR(COALESCE(?name, ""))), "теплопроводн")
         || CONTAINS(LCASE(STR(?plain)), "теплопроводн"))
}
LIMIT 10
```

```python
from mathkg.registry import query_tool

@query_tool(name="find_formula", author="Фамилия И. О.")
def find_formula(name: str, limit: int = 10) -> list:
    """Формулы набора по имени или фрагменту записи: номер, LaTeX, статья."""
    q = FIND_FORMULA.replace('"теплопроводн"', '"' + name.lower().replace('"', '') + '"')  # запрос выше
    return sparql_select(q.replace("LIMIT 10", f"LIMIT {int(limit)}"))                   # функция этапа 8
```

**Этап 9.** Формула векторизуется через контекст: «Заголовок статьи. Предложение с формулой. Имя
формулы. Запись формулы»; одиночные обозначения не векторизуются. **Этап 10.** Запрос «уравнение
теплопроводности с переменным коэффициентом» находит формулы по имени и описаниям переменных.
**Этап 11.** Агент вызывает `find_formula` и `name_formulas`.

**Этап 12.** Инструменты `extract_formulas`, `find_formula` и `name_formulas` входят в MCP-сервер группы. Агент обработки на новой статье вызывает base, затем `extract_formulas` и `name_formulas` и отвечает, какие уравнения в ней рассматриваются.

## Ручной эталон

На 10 статьях размечаются выключные уравнения (тип), строчные формулы-отношения в двух-трёх
абзацах каждой статьи и переменные с описаниями. Ожидается 80–200 выключных формул, из них
уравнений около половины, 30–60 строчных формул, 20–50 переменных.

```json
{"doc_id": "S0004", "pred": "rdf:type", "subj_quote": "T(x,1) = T(1,x) = x", "obj": "moc:Equation"}
{"doc_id": "S0004", "cls": "moc:Formula", "quote": "x ∈ [0,1]"}
{"doc_id": "S0009", "cls": "moc:Variable", "quote": "u(x, t) — температура"}
```

Имена формул записываются отдельным файлом `gold/m05_names.jsonl` (`{"doc_id", "number", "name"}`) и
проверяются своей функцией: имя считается верным, если совпадает ключ `normalize_name`.

Спорные случаи: система уравнений с одним номером — одна формула; неравенство с «=» внутри
(«a ≤ b = c») — `moc:Formula`; формула внутри утверждения размечается так же, как вне его.

## Критерии приёмки

* `check_module("extract_formulas", …)` проходит, среднее время не больше 2 с.
* Класс уравнения у выключных формул: F1 не ниже 0,85.
* Строчные формулы: точность не ниже 0,8.
* Переменные с описанием: F1 не ниже 0,5.
* Имена формул с номером, найденные правилами и языковой моделью, верны не меньше чем в 60 % случаев
  на выборке эталона; список ложных формул base передан руководителю.

## Вопросы агенту и контрольные запросы

Вопросы агенту:

1. Какое уравнение рассматривается в статье S0009 и что означают его переменные?

3. Какая формула имеет номер (2.3) в статье S0004 и где на неё ссылаются?
4. Какие уравнения типа Навье — Стокса встречаются в наборе?
5. Как в статьях набора записывается условие устойчивости через функцию Ляпунова?

Контрольные поисковые запросы (релевантны формулы с контекстом):

1. уравнение теплопроводности с граничным условием Дирихле;
2. неравенство для производной функции Ляпунова;
3. граничное условие для треугольной нормы с нейтральным элементом;
4. определение PageRank через стационарное распределение;
5. формула линейной комбинации треугольных норм.

## Связь с другими модулями

Модуль 5 зависит только от base и опирается на её выключные формулы и номера. Модуль 8 разрешает
ссылки «(2.3)» по номерам base; имена формул модуля 5 сверяются с именованными результатами
модуля 9. Ошибки выделения формул, номеров и LaTeX в base — главная тема переписки студента с
руководителем: студент передаёт список случаев с `doc_id`, страницей и текстом строки.
